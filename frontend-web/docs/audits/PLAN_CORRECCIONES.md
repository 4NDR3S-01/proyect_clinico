## Estrategia de caché propuesta para revisión

TanStack Query **no está instalada**. Su adopción sería razonable tras establecer métricas de tráfico y pruebas de aislamiento: claves por usuario/rol y recurso, `staleTime` corto según sensibilidad, filtros completos en la clave, cancelación de GET, `keepPreviousData` solo con etiqueta clara, invalidación de Pacientes/Historial/Citas/Actividades/Caja/Reportes/Dashboard tras escrituras y `queryClient.clear()` al logout/401/cambio de usuario. No persistir contenido clínico en almacenamiento del navegador. Ver [AUDITORIA_RENDIMIENTO.md](AUDITORIA_RENDIMIENTO.md) para claves y ventanas tentativas; son propuestas, no contratos.

## Verificación de cada fase

Ejecutar `npm run lint`, `npm test`, `npm run build`, `npx tsc --noEmit -p tsconfig.app.json`, `git diff --check`. Para cambios de red/seguridad, revisar además `npm audit`/`npm audit --omit=dev`, tests de promesas diferidas y matriz de roles; para UI, navegador 390/768/1280/1920 y zoom 200 % con entorno autorizado. Medir solicitudes y latencia antes/después sin publicar datos personales ni tokens. **No dar por corregido un hallazgo solo porque la suite existente permanezca verde.**
