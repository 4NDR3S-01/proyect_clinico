## Forma de respuesta, errores y tipos

- Laravel utiliza paginación estándar en `/pacientes` y `/usuarios` (`PacienteService::listar`, `UsuarioService::listar`), 20 registros por página. El esquema compartido `src/services/pagination.ts` exige metadatos de paginación; si faltan, la UI muestra error en vez de afirmar que no hay registros.
- Modelos monetarios `Actividad`/`Egreso` se serializan con casts decimales en Laravel; reportes usan `number_format` con dos decimales. Frontend admite `string|number` para registros de actividad/gasto y cadenas en resumen; no se halló en lectura estática una discordancia demostrada. No se probaron importes extremos, locales o precisión end to end.
- 401 y 403 se centralizan como eventos; 404/409/422 se tratan localmente según módulo. Un 403 no bloquea permanentemente la aplicación (`AppRouter.tsx:62-90`). La UI no reemplaza el middleware de Laravel.
- `AuthController::login` acepta cualquier contraseña string no vacía; los flujos de **alta/cambio** sí pueden tener políticas más fuertes. La desalineación está documentada en WEB-014 y requiere decidir si admitir cuentas heredadas.
- No se localizó un endpoint usado por el frontend que esté ausente de `routes/api.php` en este SHA. Tampoco se detectó llamada web a endpoints de diagnósticos, odontograma o tratamientos fingiendo integración. Esta conclusión es estática y se limita a las llamadas encontradas en `*Service.ts`.

## Condiciones no verificadas y propiedad de cada problema

No se inspeccionaron respuestas vivas, configuración de despliegue, middleware instalado en servidor ni base de datos. Un contrato puede variar si el backend desplegado no coincide con `origin/backend`. Requiere confirmar en entorno autorizado: errores 422 reales de cada formulario, serialización nullable de registros antiguos, tamaño/latencia de fotos, duplicados tras pérdida de respuesta y políticas de sesiones. El coste de `GET /usuarios` depende del volumen de usuarios y de índices Laravel; el **barrido completo desde el cliente** sí es frontend (WEB-004). Las rutas declaradas en backend que el frontend no utiliza no se consideran funcionalidades faltantes de esta auditoría.
